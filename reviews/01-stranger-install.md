# Stranger install review

Verdict: yes, a stranger can install Reckon and run estimate, gate, record and report on the sample exactly as documented today, but they cannot answer the README's third question ("Were the estimates any good?") for their own work, and a live session on a model newer than the price table is recorded at $0.00 without a word of warning.

## How this was run

Reviewed on 27 September 2026 against `main` at 7d1c9f9 (v1.2.1). The machine was a Linux x86_64 container with Python 3.11.15, git and Claude Code on PATH, and no `~/.claude/CLAUDE.md`. It was not a Mac, which is the only platform the README names. I followed README.md, then docs/QUICKSTART.md where the README sends the reader, in a fresh `git clone` from GitHub into an empty folder. I repeated the install with Python 3.9.23 and pip pinned to 21.2.4, the pip the Quickstart says macOS ships, to test the claim that the pip upgrade line is needed.

What worked, briefly, so the list below reads in proportion. The six install lines ran cleanly on Python 3.11 and on Python 3.9. With pip 21.2.4 and the upgrade line skipped, `pip install -e .` failed with "editable mode currently requires a setuptools-based build", which is exactly the failure the README warns about; with the upgrade line it succeeded. `reckon estimate` matched the README capture to the cent. All three `reckon gate` captures matched, including exit codes 2, 0 and 2, and the form without Claude Code matched once I took it off PATH. `reckon record --source sample/session` and `reckon report --sample` matched the Quickstart. `git status` stayed empty after every Quickstart command. The five test suites passed on both Pythons: 758 tests, 1 skipped.

The three things the README says a new user wants (the "Why" section, README.md lines 43 to 48) were tried on the sample: price and gate a piece of work before it starts, find what a session cost, and check whether the estimates were any good. The first two work. The third works only on the shipped sample.

## Findings, worst first

1. The third headline question cannot be answered for your own work, and nothing tells you so until you are deep in the Quickstart. README.md line 47 says "Every estimate is logged beside its actual". I ran `reckon estimate` and `reckon gate` and checked for new files: neither writes anything. `reckon report` on my own store printed "No tasks in this store yet, so there is no estimate to compare a recorded cost with." The only admission is QUICKSTART.md lines 264 and 265 ("task records linked to runs, which this version does not create for you"). `reckon record` then tells the user to "add the link in ledger/run-tasks.json" (ledger/recorder.py line 945, captured at QUICKSTART.md line 167), but that file does not exist in a fresh clone and no document describes its format. Change README.md line 47 to say that this version logs estimates beside actuals only for tasks whose runs you link by hand, and add a short section to docs/QUICKSTART.md after line 265 giving the format of `ledger/run-tasks.json` with one worked example, or remove the pointer from ledger/recorder.py line 945.

2. The Quickstart writes an invented session into the user's own permanent register, and never says how to take it out. Step: `reckon record --source sample/session` (docs/QUICKSTART.md line 157). It created R-0001 in `runs/2026-09.jsonl` and `store/refs.json`. When I then ran `reckon record` on my own transcripts and `reckon report`, the report said "Runs recorded: 1, $0.01 at list rates", and that one run is the invented sample, not mine. My real runs will start at R-0002. The README sells the store on its integrity (permanent references and append-only logs, README.md line 92 and lines 77 to 82), so a stranger will reasonably be afraid to delete these files by hand. Either run this step against a throwaway store, or state at docs/QUICKSTART.md lines 152 to 154 that it writes into the same store your own work goes into, and give the exact files to delete before recording your own sessions.

3. A live session on a current model is costed at $0.00 with no warning on screen. Step: `reckon record` with no `--source` (docs/QUICKSTART.md line 231), run inside the Claude Code session doing this review. Output: one run, "$0.00 total at list rates", and no WARNING line. The Run record in `ledger/runs.json` holds `"unpriced_models"` naming the session's model, which is newer than every entry in `ledger/prices.json`. `ledger/aggregate.py` lines 501 to 503 already print "unpriced model(s) contributed ZERO cost" for the same case; `ledger/recorder.py` collects the same list (line 397) and never prints it. The docs say "prices each message's tokens at published list rates" (README.md line 95) and do not mention that an unlisted model counts as free. Add the aggregate.py warning to the summary block in ledger/recorder.py, next to the other WARNING lines at lines 947 to 957, and add one sentence at docs/QUICKSTART.md line 240 telling the user to check `ledger/prices.json` covers the models they use.

4. A command in the settings page dirties the download and rewrites the provenance of the shipped figures. docs/SETTINGS.md line 27 says to run `python ledger/recorder.py --priors --write-priors`. On a fresh clone (after the Quickstart's record step) it printed `{}`, then "priors written to .../wrapper/gate.json". `git status` then showed `M wrapper/gate.json`: both shipped priors changed `source` from "derived by ledger/recorder.py from Run records" to "hand-carried", and `priors_basis` now cites `ledger/preflight-ledger.md`, which is not in the repository. docs/QUICKSTART.md lines 34 to 37 say `reckon` refuses to run any way other than the editable install, yet docs/SETTINGS.md lines 15, 27 and 38 send the reader straight to `python ledger/recorder.py`, `python ledger/aggregate.py` and `python estimator/estimate.py --fit`, which do run. Change docs/SETTINGS.md line 27 to warn that on a fresh install this overwrites the shipped priors and marks them hand-carried, and change line 15 to point at `reckon record`, which is what the Quickstart uses.

5. The Quickstart describes the prompt `--execute` sends wrongly, and leaves two sample fields in the user's own task. docs/QUICKSTART.md line 283 says the text under the second `---` "is the prompt `--execute` sends". The command the gate prints is `claude -p "$(cat my-tasks/my-task.md)"`, and wrapper/launch.py line 405 passes `task_path.read_text()`, the whole file: front matter goes to Claude Code as part of the prompt. The same section (lines 275 to 281) lists only `ref`, `brief` and `est_p95_usd` to change. My copy kept `project_ref: P-0001` and `task_class: investigation` from the sample, and the gate priced it against the sample's `investigation` prior (with `est_p95_usd` removed it said "prior for 'investigation' has n=1"). Correct line 283 to say the whole file is sent, and add `project_ref` and `task_class` to the list at lines 277 to 280 with what each is for.

6. Platform support is unstated beyond macOS. README.md line 14 and docs/QUICKSTART.md lines 5 and 14 say "On macOS, in Terminal" and nothing about anything else. The install ran unchanged on Linux, and .github/workflows/tests.yml line 8 shows CI runs on `ubuntu-latest`, so Linux works and the README hides it. Windows is not mentioned; `source .venv/bin/activate` is not the Windows form. On Linux, `reckon usage` looked in `/root/Library/Application Support/Claude/` and reported "NO SOURCE EXISTS", correct but only after a Mac path appears on a Linux screen (docs/QUICKSTART.md line 217 does say "on a Mac"). Add one sentence at README.md line 14 naming Linux as tested in CI, saying whether Windows is supported, and saying that `reckon usage` reads the desktop app's file on a Mac only and needs `--paste` elsewhere.

7. The Quickstart's estimate capture is stale. docs/QUICKSTART.md lines 52 to 59 show the pieces at $8.14 and $8.14 and the range as $4.89, $16.28 and $52.45. The real output on this clone, and README.md lines 107 to 115, show $8.26 and $2.75, then $3.37, $11.01 and $35.03. README.md lines 34 and 170 promise "actual captured output" and docs/QUICKSTART.md line 39 says every command below ran against the sample. Replace docs/QUICKSTART.md lines 52 to 59 with the output the README already shows.

8. README.md line 96 contradicts the repository twice. It says `session/` holds "one invented Claude Code session"; `sample/session/reckon-sample/` holds two, and docs/QUICKSTART.md line 149 says two. It also refers to "the gate table below", but there is no table below it in the README; the table is in sample/SAMPLE.md lines 28 to 32, and the README shows a single gate capture. Change "one invented Claude Code session" to "two invented Claude Code sessions" and "the gate table below" to "the gate table in `SAMPLE.md`".

9. The gate lets a task through with nobody named as approver, and the Quickstart tells the user to keep it that way. Every sample task, and so the user's copy, has `state: approved` with `approved_by: null` and `approved_at: null`, and the gate answered ALLOW or ASK on the state alone. docs/QUICKSTART.md line 282 says to leave `state: approved` as it is and says nothing about the approver fields, while README.md lines 50 to 52 say Reckon records "who approved it". Add a line at docs/QUICKSTART.md line 282 telling the user to fill `approved_by` and `approved_at`, or say plainly that the gate does not check them.

10. `reckon status` and `reckon gate` point at tools the docs never introduce. `reckon status` printed "no refusal-based estimate on file (ledger/limits.py writes one)" (ledger/usage_status.py line 251); no document says how or when to run `ledger/limits.py`. With no estimate in a task file, `reckon gate` told me to run `python3 ledger/recorder.py` and "link them in ledger/run-tasks.json", neither of which the Quickstart uses. Either document `ledger/limits.py` in docs/USAGE.md, or change the message at ledger/usage_status.py line 251 to name a `reckon` command.

11. The README and the method disagree on how wide the ranges are. README.md line 66 says the top of a typical range "was about ten times the bottom"; docs/METHOD.md line 80 says "about six times". The README capture fits ten times in dollars ($35.03 against $3.37) and about five times in turns (89 against 17), so one is probably cost and the other turns. Say which in both places, README.md line 66 and docs/METHOD.md line 80.

12. The block answer cannot be seen from the sample, and the sentence explaining why is hard to parse. docs/QUICKSTART.md lines 71 to 73 say the three examples run on copies "each with its state changed to `approved` -- the tasks themselves shipped, and the gate blocks a shipped task on sight". A first-time reader takes "shipped" to mean "came with the package". The originals are not in `sample/tasks/`, so there is no file to see BLOCK on; I had to make one by changing `state` to `draft` (it blocked with exit code 3). Reword to "the original tasks are in the state `shipped`, which the gate blocks", and add a fourth capture showing BLOCK, perhaps on a copy with `state: draft`.

13. Two small rough edges. `reckon --version` fails with "unrecognized arguments" (reckon/cli.py, `main` at line 105), which is the first thing many people type. Piping gate output into `head` ends in a `BrokenPipeError` traceback from wrapper/launch.py line 347. Neither blocks use.
